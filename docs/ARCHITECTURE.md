# Архитектура 220 · size-chart-comparator

## Схема

```
index.html → src/main.tsx → App.tsx (#data, #map, #compare, #card)
                │
                ├─ ui/useChart.ts ── core/store.ts ── IndexedDB «size-chart-comparator» (+ копия в localStorage на pagehide)
                │
                └─ useAnalysis ── core/measurement-compare.ts: analyze(chart)
                                     ├─ core/chart-editor.ts     модель, нормализация, сопоставления, загрузка таблиц
                                     └─ core/unit-conversion.ts  разбор значения, точные мм, округление, порог
                   core/chart-export.ts  CSV сравнения, таблица для карточки, печать (CSS @media print)
```

## Модель данных

| Сущность | Поля | Замечания |
|---|---|---|
| `Supplier` | `id`, `name` | имя уникально без учёта регистра |
| `Row` | `supplierId`, `model`, `size`, `label`, `value`, `unit` | строка таблицы поставщика как есть; `value` — строка («48,5», «19 1/2», «» — нет данных), `unit` — `cm` или `in` |
| `MeasureType` | `id`, `name` | общие типы: «Грудь», «Талия», «Длина изделия», «Рукав» и свои |
| `Mapping` | ключ «поставщик + название замера» → `typeId`, `method` | `method`: `flat` (по плоскости), `girth` (по обхвату), `length` (по длине) |
| `Settings` | `threshold`, `thresholdUnit`, `rounding`, `show` | порог строкой и его единица, округление до мм, единица показа |

## Расчёт: `analyze(chart)`

```
для каждой строки:
  сопоставление (поставщик, normText(название)) нет или тип удалён → неоднозначная «тип не сопоставлен»
  toMm(значение, единица, округление): ошибка → неоднозначная «неверное значение»
                                       пусто   → «нет данных»
  ячейка = (поставщик, normText(модель), normSize(размер), тип, способ)
ячейка с двумя и более строками → неоднозначная «конфликт», в сравнении «конфликт строк»
группа = (модель, размер, тип, способ): значения поставщиков в мм
  разброс = max − min, если значений ≥ 2, иначе «мало данных»
  больше порога ⇔ разброс > порог (точная дробь в мм)
```

Перевод: значение разбирается в дробь `n/d` (48,5 → 97/2, 19 1/2 → 39/2), мм = `n·10/d` для см и `n·254/(10·d)` для дюймов, округление в целых числах. Поэтому 19 1/2″ = 495,3 мм → 495, а 0,05 см = ровно 0,5 мм → 1 при «до ближайшего». Порог тоже точная дробь: 0,75″ = 19,05 мм, разброс 20 мм больше, 19 — нет.

## Отображение и экспорт

Единица показа меняет только вывод: мм → «48,0» (см, один знак), «19,49» (дюймы, два знака), «480» (мм). Заголовки столбцов всегда с единицей, тип — со способом: «Грудь, см (по плоскости)». CSV: «;», BOM, кавычки, ячейки с `= + - @` в начале экранируются апострофом. Печать — `window.print()`, стили `@media print` оставляют только таблицу.

## Хранение

Как в остальных браузерных проектах пакета: IndexedDB, правки полей сохраняются через 300 мс, действия сразу. Следующее состояние считается от последнего до `setState`, на `pagehide` проект копируется в localStorage, при открытии берётся более новая версия. Без IndexedDB — работа в памяти с предупреждением. Файл проекта JSON проверяется `parseChart`: битые строки, неизвестный поставщик или версия не загружаются, настройки с неверными значениями заменяются значениями по умолчанию.

## Решения и причины

| Решение | Причина |
|---|---|
| Значение хранится строкой | человек видит то, что ввёл («19 1/2», «48,5»), а перевод и округление можно поменять без потери исходных данных |
| Сопоставление по паре «поставщик + название» | «Грудь» у одного поставщика — полуобхват, у другого — обхват; одно название у разных поставщиков может значить разное |
| Способ измерения — часть ключа сравнения | 48 см по плоскости и 96 см по обхвату — одна и та же грудь, сравнивать их разбросом нельзя |
| Конфликт исключает обе строки | какое из двух значений верное, приложение не знает: решает человек |
| Кэш нормализации и перевода, отложенный анализ на больших проектах | на 36 000 строк полный анализ на каждую букву давал 258 мс задержки ввода (см. приёмку, раунд 4) |
