# Правила работы с проектом 220 Сравнение размерных сеток

Браузерное приложение React + TypeScript + Vite без сервера. Проект — IndexedDB, перенос — файл JSON.

## Где что находится

- Интерфейс и публичные маршруты — `index.html`, `src/main.tsx`, `src/App.tsx` (`#data` — замеры поставщиков, `#map` — сопоставление и неоднозначные строки, `#compare` — сравнение, `#card` — таблица для карточки товара), `src/ui/useChart.ts`, `src/styles.css`.
- Предметная логика и хранение — `src/core/chart-editor.ts`, `src/core/unit-conversion.ts`, `src/core/measurement-compare.ts`, `src/core/chart-export.ts`, `src/core/store.ts`.
- Данные, ассеты и демоматериалы — демо `demoChart()` в `src/core/chart-editor.ts`, иконка `public/favicon.svg`, готовая сборка `dist/`.
- Тесты и документация — `src/core/core.test.ts` (Vitest), `e2e/*.spec.ts` (Playwright), `docs/`.

## Команды и сценарий

- Установка — `npm ci`, для e2e один раз `npm run e2e:install`.
- Запуск и адрес — `npm run dev` → http://localhost:5220/; готовая сборка `npm run serve:dist` → http://127.0.0.1:4320/.
- Проверки и сборка — `npm run typecheck`, `npm test`, `npm run build`, `npm run e2e` (порты 4320 и 4420), всё вместе `npm run verify`.
- Данные и результат показательного сценария — «Загрузить демо» → «Сравнение», порог 2 см: M «Грудь» 48,0 / 52,0 / 49,5 см, разброс «4,0 — больше порога»; L «Длина изделия» 70 и 72 см — 2,0 без подсветки; у «Вязальщика» M «Рукав» — «нет данных»; «Сопоставление» — 2 неоднозначные строки.

## Инварианты проекта

- `analyze(chart)` — единственный расчёт: сравнение, сводка, бейдж и список неоднозначных строк, CSV и таблица для карточки читают его результат.
- Значение хранится строкой, как ввёл человек. В мм переводится точной дробной арифметикой (1 дюйм = 25,4 мм ровно), затем округляется до целых мм по настройке (до ближайшего — половина вверх, вниз, вверх). Порог не округляется, подсветка — строго больше порога.
- Сравниваются только строки с одинаковым типом и одинаковым способом измерения (по плоскости, по обхвату, по длине). Тип и способ задаются сопоставлением «поставщик + название замера».
- Группа сравнения — (модель, размер, тип, способ). Модель без учёта регистра, ё/е и пробелов, размер — с приведением кириллических «М», «Х» к латинице и 2XL/3XL к XXL/XXXL.
- Неоднозначные строки (не сопоставлен тип, неверное значение, две и больше строк одного поставщика на одну ячейку) в расчёт не входят и выводятся на «Сопоставлении». Пустое значение — не ошибка, а «нет данных»: не участвует в разбросе, остальные строки сохраняются.
- Экспорт CSV: «;», BOM, защита от формул апострофом, единица и способ в заголовках, имена файлов латиницей.
- Сохранение: следующее состояние считается от `latest.current` до `setState`. Действия сохраняются сразу, правки полей — через 300 мс, на `pagehide` проект целиком пишется в localStorage.
- На проектах от 5 000 строк ввод текста пересчитывает анализ через 250 мс после последней правки, действия — сразу (`useAnalysis` в `App.tsx`).
- Сборка с `base: './'`: e2e-проекты `nested-path` и `root-path`.
