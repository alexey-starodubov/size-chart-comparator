# 220 · Сравнение размерных сеток

`size-chart-comparator` — браузерное приложение без сервера. Продавец вносит замеры одного товара у нескольких поставщиков (ширина груди, длина, рукав…) в сантиметрах или дюймах, сопоставляет названия замеров поставщиков с общими типами и способом измерения и видит, где одинаковая маркировка размера скрывает разные изделия. Значения переводятся в целые миллиметры с выбранным округлением, разброс больше порога подсвечивается, пропуски показываются как «нет данных». Таблицу замеров одного поставщика для карточки товара можно выгрузить в CSV или напечатать. Данные хранятся в IndexedDB браузера и сохраняются в файл JSON.

## Быстрый старт: готовая сборка

Готовая статическая сборка лежит в папке `dist/` (входит в ZIP-выпуск, в git не коммитится). Открывайте её через локальный HTTP-сервер.

```bash
node scripts/serve-static.mjs --dir dist --port 4320 --base /   # Node.js 22.12+
# или: python3 -m http.server 4320 --directory dist
# открыть http://127.0.0.1:4320/
```

Сборка использует относительные пути и работает и из корня сайта, и из вложенного пути вроде `https://<user>.github.io/size-chart-comparator/`.

## Демонстрационный сценарий

1. **«Загрузить демо»**: три вымышленных поставщика «Футболки базовой» и «Худи оверсайз». «Ткани Севера» и «Хлопок-Юг» пишут в сантиметрах («Ширина груди» и «Полуобхват груди»), «Вязальщик» — в дюймах («Chest width», «19 1/2») и кириллической «М» вместо латинской.
2. «Сравнение», порог 2 см: у размера M «Грудь (по плоскости)» — 48,0, 52,0 и 49,5 см, разброс **«4,0 — больше порога»**, строка подсвечена. Это приёмка ТЗ: M 48 и 52 см при пороге 2 см.
3. У размера L «Длина изделия» 70,0 и 72,0 см — разброс ровно 2,0 см, на пороге не подсвечивается. Порог 1,9 — подсвечивается.
4. У «Вязальщика» для M нет длины рукава: ячейка «нет данных», разброс считается по двум остальным. «Показывать в» → мм или дюймы меняет только отображение.
5. Баннер «Неоднозначных строк: 2» ведёт на «Сопоставление»: у «Хлопок-Юг» две строки «L, Полуобхват груди» (54 и 55) — конфликт, ячейка в сравнении «конфликт строк». «Удалить эту строку» у одной из них возвращает L в расчёт. «Обхват бёдер» не сопоставлен: выберите тип (или добавьте «Бёдра») и способ «по обхвату».
6. «Для карточки товара»: модель, поставщик, единица — таблица «Размер × замеры» с подписями «Грудь, см (по плоскости)». «Скачать CSV» и «Печать» (печатается только таблица).

Свои данные: «Новый поставщик», затем строки по одной («Новая строка», после добавления фокус на размере, модель и замер сохраняются) или «Вставить таблицу поставщика» — строки `модель;размер;замер;значение;единица`, копируются из Excel табуляцией.

## Разработка, проверки и сборка

Требования: Node.js 22.12 или новее, npm 10+.

```bash
npm ci                      # зависимости строго по package-lock.json
npm run dev                 # http://localhost:5220/
npm run typecheck
npm test                    # Vitest: единицы и округление, порог, сравнение, неоднозначности, загрузка таблиц, экспорт
npm run build               # сборка в dist/
npm run e2e:install         # один раз: Chromium для Playwright
npm run e2e                 # Playwright по dist/: вложенный путь /size-chart-comparator/ и корень (порты 4320, 4420)
npm run verify              # всё подряд
```

## Где что лежит

| Путь | Назначение |
|---|---|
| `src/core/chart-editor.ts` | модель: поставщики, строки, типы, сопоставления; правки, загрузка таблицы, файл проекта, демо |
| `src/core/unit-conversion.ts` | разбор значений (48,5 · 19 1/2 · 19½"), точный перевод в целые мм, округление, порог |
| `src/core/measurement-compare.ts` | `analyze(chart)` → неоднозначные строки, группы сравнения, разброс, превышение порога |
| `src/core/chart-export.ts` | CSV сравнения, таблица для карточки товара, имена файлов |
| `src/core/store.ts`, `src/ui/useChart.ts` | IndexedDB, автосохранение, копия на закрытие вкладки |
| `src/App.tsx` | интерфейс: замеры, сопоставление, сравнение, карточка товара |
| `e2e/` | Playwright |
| `docs/` | карточка, архитектура, приёмка, ассеты, исходное ТЗ |
